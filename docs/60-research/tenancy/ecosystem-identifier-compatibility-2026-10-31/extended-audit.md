# Additional Nightscout identifier consumers and writers

**Reference appendix to the [main ecosystem inventory](../ecosystem-identifier-compatibility-2026-10-31.md), 31 October 2026.**

These repositories preserve the broader audit without making every integration a main coordination participant. Inclusion shows a source pattern, not substantial adoption or current installed use. A decoder/type declaration is distinguished from an operational lookup, mutation or dedupe path.

## Additional operational identity paths

| Repository | Reviewed dependency | Compatibility implication |
| --- | --- | --- |
| [GlycemicGPT](https://github.com/lumose-health/GlycemicGPT) | Incremental treatment fetch uses and validates 24-hex `_id` values as a cursor. [client](https://github.com/lumose-health/GlycemicGPT/blob/d1a9adb73e46abc0599e493a095e4ef887e08762/apps/api/src/services/integrations/nightscout/client.py). | Arbitrary client UUIDs or changed ordering cannot simply replace an ObjectId cursor. |
| [LoopEval](https://github.com/loopkitdev/LoopEval) | Reads `_id` and decodes the first eight hexadecimal characters as an insertion time; carb identity also uses `_id`. Analysis code inspects `syncIdentifier` to recognize suspend events. [client](https://github.com/loopkitdev/LoopEval/blob/44f72d4b74eefe4e794555357aa8c58b04326f9c/Sources/EvalCore/DataSource/NightscoutClient.swift); [carb identity](https://github.com/loopkitdev/LoopEval/blob/44f72d4b74eefe4e794555357aa8c58b04326f9c/Sources/EvalCore/DataSource/NightscoutEvalDataSource.swift); [analysis](https://github.com/loopkitdev/LoopEval/blob/44f72d4b74eefe4e794555357aa8c58b04326f9c/analysis/loopeval_analysis/nightscout_export.py). | ObjectId shape does not prove ObjectId timestamp semantics when clients synthesize those strings. This is a compatibility risk, not a reproduced failure. |
| [loop-cr-review](https://github.com/peisenh/loop-cr-review) | Export deduplication uses `_id`, with full JSON as a fallback. [exporter](https://github.com/peisenh/loop-cr-review/blob/dfa716228d93ca1a96431ff66518e2292311ee79/tools/fetch-nightscout.py). | Different ID response shapes can change export dedupe. |
| [ha-nightscout-v3](https://github.com/savek-cc/ha-nightscout-v3) | SQLite history uses `identifier` as the primary key and skips entries without it. [history store](https://github.com/savek-cc/ha-nightscout-v3/blob/57a17f072f32019937a1fed3e2952e38bb150e04/custom_components/nightscout_v3/history_store.py). | This custom integration has a direct dependency, unlike the official Home Assistant SGV path described in the main inventory. |
| [cgm-bridge](https://github.com/solazs/cgm-bridge) | Entry processing prefers `_id`, falls back to `identifier`, and skips records lacking both. [processor](https://github.com/solazs/cgm-bridge/blob/3a3f03b5848a0141bc0f0b45a392597ae6836050/src/cgm_bridge/nightscout.py). | Key preference and field availability affect processing. |
| [cgm-relay](https://github.com/yaanfpv/cgm-relay) | Synthesizes entry `_id` as a 24-hex rendering of Unix seconds. | [AAPSClientiOS](https://github.com/JetFoxy/AAPSClientiOS) | Mapping selects `identifier`, then `_id`, then a generated UUID. Treatment creation can omit client identity. [mapping](https://github.com/JetFoxy/AAPSClientiOS/blob/34d1864e57c13715dbe666e7db100d530fdc6227/Shared/Domain/NsMapping.swift); [writer](https://github.com/JetFoxy/AAPSClientiOS/blob/34d1864e57c13715dbe666e7db100d530fdc6227/App/Treatments/NsTreatmentWriterLive.swift). | A separate project from Android AAPSClient, with different fallback and create behavior. |
| [TidepoolToNightScoutSync](https://github.com/skalahonza/TidepoolToNightScoutSync) | Retains profile `Id`, mapped from `_id`, when updating a profile. [syncer](https://github.com/skalahonza/TidepoolToNightScoutSync/blob/05fdadb4e5bc900034ccd9981194f4357885883c/src/Core/Services/TidepoolToNightScoutSyncer.cs); [profile model](https://github.com/skalahonza/TidepoolToNightScoutSync/blob/05fdadb4e5bc900034ccd9981194f4357885883c/src/Core/Model/Nightscout/Profile.cs). | Profiles need their own identity/update test rather than an entries-only migration. |

## Reviewed paths without a demonstrated direct identifier dependency

These still illustrate why an identifier must not become mandatory on existing create routes without a transition:

- [Companion FX](https://github.com/SandraK82/Companion_FX) constructs glucose/treatment JSON without a common record identifier in the reviewed serializer. [serializer](https://github.com/SandraK82/Companion_FX/blob/126cb191b15b7650c75bdf961abc2a477024d120/app/src/main/java/com/diabetesscreenreader/data/GlucoseReading.kt).
- [ottai-nightscout-uploader](https://github.com/pmakhotkin/ottai-nightscout-uploader) constructs glucose entries without one. [uploader](https://github.com/pmakhotkin/ottai-nightscout-uploader/blob/19da1437404b29ce87a13568cf7c7c0e02007825/module.py).
- [carelink-bridge](https://github.com/domien-f/carelink-bridge) transforms source readings into entries without a client identity field. [transformer](https://github.com/domien-f/carelink-bridge/blob/ab698ffd110514b8c0cfacfdd43691db4b09195d/src/transform/index.ts).
- [DiaBLE](https://github.com/gui-dos/DiaBLE) has a no-ID upload path, but the repository is archived. [implementation](https://github.com/gui-dos/DiaBLE/blob/e6a909c88faeada49f461d30834174cd95db4042/DiaBLE/Nightscout.swift).

The py-nightscout SGV model used by the official Home Assistant integration, ps2/python-nightscout and ivalkou/NightscoutAPIClient did not establish an identifier-name dependency in the reviewed paths. Discovery of a Nightscout string in a repository is not enough to call it impacted.

## Exclusions and follow-up boundaries

- **airmed-dev/meals:** an entry model contains `_id`, but the reviewed integration methods return “Not implemented”. It is not counted as an operational integration. [stub](https://github.com/airmed-dev/meals/blob/d76fa654265f0badfb5f6af8aeb7698b5042f669/meals/Integrations/Nightscout.swift).
- **Legacy NightWatch:** the StephenBlackWasAlreadyTaken repository is not the current Play Store app sharing the name. Neither historical code nor a modern store listing can stand in for the other's behavior.
- **Glimp and Diabox:** proprietary legacy apps in the official Nightscout documentation; no current source audit asserted.
- **Other current commercial followers and watch apps:** the [official directory](https://nightscout.github.io/nightscout/downloaders/) also lists products such as Enhance-d, Sugar Sense and Nightscout X. Their presence justifies a follow-up supported-configuration check, not a claim that a particular identifier is required.
- **AAPS forks, copied uploaders and unverified search hits:** retain as discovery leads only when they add an independent wire behavior or a concrete installation compatibility case. Do not multiply the coordination list by counting every code copy.
